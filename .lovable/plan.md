# Balance Roost's two-sided positioning in memory and LANI outreach

## Context

Roost must present itself as a balanced platform serving both renters and landlords, even when speaking to a landlord body like LANI. The current LANI email draft leans heavily into landlord burden-reduction and does not make the renter-side value explicit.

## What we will change

1. **Project memory** — add a core rule: "Roost is always positioned as a two-sided workspace; renter benefit and landlord benefit are stated together, even in landlord-facing copy."
2. **docs/positioning.md** — add a "Two-sided balance" section stating both sides pay, both sides benefit, and neither is the product.
3. **LANI email draft** — revise the middle paragraphs so the renter value (Tenant Passport, reusable application, transparent screening) appears alongside the landlord value, and clarify that the platform's neutrality comes from serving both.
4. **Beta landing page** — review; no changes expected unless it is found to under-weight the renter path.

## Out of scope

- No UI component changes
- No database or backend changes
- No new features

## Deliverables

- Updated `mem/index.md`
- Updated `docs/positioning.md`
- Updated `/mnt/documents/roost-ni-lani-email-draft.md`
